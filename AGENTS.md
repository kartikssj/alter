# AGENTS.md

Guidance for agents/developers working on Alter.

## What this is

macOS window switcher app (Swift, AppKit + SwiftUI views, zero third-party dependencies). Global hotkey summons a floating panel listing windows (icon + app name + title); releasing the modifier activates the selection.

## Build & verify

- `make build` — xcodebuild, Debug, into `build/`. Must end with `BUILD SUCCEEDED`.
- `make run` — build + `open` the app. `make clean` wipes `build/`.
- `make release` — Release build into `build/`, zip into `dist/Alter-<version>.zip` + SHA-256. **Must pass `-destination 'generic/platform=macOS'`** or xcodebuild 26 picks "My Mac (arm64)" and silently ships an arm64-only binary (verified: `lipo -info` must show `x86_64 arm64`). Version comes from `MARKETING_VERSION` in the pbxproj (bump there, tag `v<version>`).
- `make cask` — prints the Homebrew cask stanza (version + sha256 filled from the dist zip) for the `kartikssj/homebrew-tap` tap repo (`Casks/alter.rb`).
- No test target. Verification is manual: press the hotkey, check the panel, confirm a switch happens.
- **LSP noise**: SourceKit reports bogus "cannot find X in scope" cross-file errors until a build indexes the project. Trust `make build`, not editor diagnostics.
- **Do not** revert to a SwiftUI `Settings` scene for the settings window: its `showSettingsWindow:` action reported handled but never materialized a window on macOS 15/Xcode 26. The self-managed `NSWindow` in `AppDelegate.showSettings()` is deliberate.

## Release signing

Debug is signed "Apple Development" (TCC-stable for local dev). Release is **ad-hoc on purpose**: the Apple Development cert in the keychain is tied to an employer team — do NOT ship release binaries signed with it. When a personal Developer ID exists: flip Release config per the comment block in the Makefile (identity, team, hardened runtime), then `notarytool submit --wait` + `stapler staple` + re-zip.

## Project layout

- `alter.xcodeproj/` — hand-written, Xcode 16+ folder-synchronized format (`PBXFileSystemSynchronizedRootGroup` on `Alter/`). **Just drop new .swift files into `Alter/`** — no pbxproj edits needed. Keep `Info.plist` at the repo root (inside the synced folder it would be bundled as a resource). **Exception:** `Themes/` is a `PBXFileReference` folder reference in the Resources phase so it bundles as `Contents/Resources/Themes/<id>/` with structure intact — do NOT move it under `Alter/` (the synced group flattens resources, and every theme's `index.html` collides).
- `Alter/Assets.xcassets/` — app icon (`AppIcon`, classic 10-slot mac format — the Xcode 14+ single-1024 slot is rejected by actool 26 with "unassigned child"). `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon` is set in the target configs. The 1024 master was rendered by a throwaway AppKit script (not committed); regenerate or replace `icon_1024.png` and `sips -z` down to the other sizes if redesigning.
- `Makefile` — build/run/clean wrapper.
- `Themes/` — showcase theme gallery (`coder`, `retro-gaming`, `fantasy`, `techno`, `nineties`, `cherry-blossom`, `book`, `cats`, `moto`, `rainbow`), raw-bridge reference implementations with bundled OFL fonts, **bundled into the app** (see the folder-reference exception above). `ThemeStore` merges bundle + user dir (`~/Library/Application Support/Alter/Themes/`), user copy wins on id collision. Run from the repo with `ALTER_THEMES_DIR=$PWD/Themes ALTER_THEME=<id>` — launch the binary directly (`build/.../Alter.app/Contents/MacOS/Alter`), as `make run`'s `open` does not forward env vars.
- Target: macOS 14.0+, Swift 5 mode, signed "Apple Development" (see Signing below).

## Architecture (data flow)

```
CGEventTap (HotkeyMonitor)
  -> SwitcherCoordinator.handle(action)
     -> show: WindowCatalog.currentWindows -> SwitcherViewModel
        -> SwitcherPanel (NSPanel + SwiftUI)            [default]
        -> ThemedSwitcherPanel (NSPanel + WKWebView)    [opt-in theme]
     -> confirm: WindowActivator.activate(entry)
     -> searchToggle: SearchCoordinator
        -> SearchPanel (NSPanel + SwiftUI, sticky)      [Opt-Space default]
        -> typing: event tap -> SearchViewModel.query
           -> SearchResultsProvider (NSMetadataQuery, system Spotlight index)
        -> confirm: NSWorkspace.open / activateFileViewerSelecting
```

- `main.swift` — plain AppKit bootstrap (no SwiftUI App lifecycle). AppDelegate builds the app menu by hand.
- `HotkeyMonitor` — `CGEventTap` on `.keyDown` + `.flagsChanged` at `.cgSessionEventTap`, head-insert, active (`.defaultTap`) so events can be **swallowed** (return nil). Trigger modifier is configurable (`.maskAlternate` default / `.maskCommand`). Modifier-release-to-confirm is detected in `flagsChanged`. Re-enables itself on tap-timeout. Backtick ignores autorepeat events (`keyboardEventAutorepeat` field) so each physical press advances exactly once; Tab keeps autorepeat (hold-to-cycle, like native Cmd-Tab). Also owns the **search hotkey** (search-trigger modifier + Space, swallowed) and, while the search panel is visible, routes keystrokes to it: Escape/Return(⌘↩=reveal)/arrows/Delete are swallowed as actions, printable characters are read via `keyboardGetUnicodeString` (layout-correct, Option-composed chars included) and swallowed; anything with Command/Control and non-printable keys pass through untouched (Cmd-Tab/Cmd-Q keep working). Switchable combos are ignored (passed through) while search is visible. **Number-key quick switch**: while the switcher is visible, trigger + digit 1-9 (and ONLY the trigger — Shift excluded so Cmd-Shift-3/4/5 system screenshots pass through) emits `jumpTo(index)`, swallowed; the coordinator selects that row and confirms immediately (the later modifier release is a no-op). Rows 1-9 show a keycap digit badge in the built-in UI; the bridge exposes `index` per window for themes that want badges.
- **Search (Spotlight-style, sticky panel)** — `SearchCoordinator` owns `SearchViewModel` + `SearchResultsProvider` + `SearchPanel`. Unlike the switcher, the panel stays open after modifier release; dismissed by Esc, the search hotkey again, confirming a result, or an outside click (global mouse monitor — a local monitor would fire on clicks inside our own non-activating panel). `SearchResultsProvider` wraps `NSMetadataQuery` (system Spotlight index, no custom index, no extra permissions): 150ms debounce per keystroke, content-type filter built from the user's enabled categories (`SearchCategories` — applications/folders/files, all on by default; all-off = no results), apps-then-folders-then-files ranking, cap 20. Category changes apply live (`SearchCoordinator.applyCategories` re-runs the open query). **MDQuery operator constraint:** `CONTAINS` on a string attribute throws an NSException in `setPredicate` (untestable in Swift, shipped as a crash) — names must use `LIKE[cd]` with `*term*` wildcards and `kMDItemContentTypeTree` membership uses `==`. An OR compound with exactly ONE subpredicate also throws ("wrong number (1) of subpredicates") — with a single enabled category, use the leaf predicate directly. `SearchPanel` is a single non-activating panel on the pointer's screen, positioned slightly above center; the "field" is rendered manually (query text + TimelineView blinking caret) because the panel never becomes key — no IME/dead-key composition or paste, that's the event-tap tradeoff. Enter opens via `NSWorkspace.open`, ⌘↩ reveals via `activateFileViewerSelecting`. Out of scope by design: calculator/unit conversion/Siri suggestions (private Spotlight features).
- **Themed search (opt-in per theme)** — a theme shipping `search.html` next to `index.html` also styles the search panel: `ThemedSearchPanel` (same skeleton/lockdown as `ThemedSwitcherPanel`, `alter-lib` + `alter-fileicon` schemes only) + `SearchBridge` push `{query, searching, selectedIndex, results:[{name, subtitle, kind, selected, iconUrl}]}` into `window.alter.update(...)` — the SAME bootstrap/handler name as the switcher bridge, so one `alter-elements.js` serves both page types (`<al-search-field>`/`<al-search-list>` consume search state; switcher elements no-op on it and vice versa). `alter-fileicon://<percent-encoded-path>` serves `NSWorkspace.icon(forFile:)` — icon images only, never file contents. `ThemeStore.Theme.searchIndexURL` is nil when the theme lacks search.html → native search; a search-page JS error/crash latches a search-local `themeFailed` (native fallback until theme change), independent of the switcher's latch. Search pages are always autoResize-sized.
- `WindowCatalog` — two CGWindowList queries merged: `.optionOnScreenOnly` (true front-to-back z-order — `.optionAll` is effectively creation order, do NOT rely on it for recency) plus `.optionAll`-only windows (minimized) appended after; `.excludeDesktopElements` on both, layer-0 only, ≥50×50pt, skips self/Dock/WindowServer. Windows that are off-screen **and** not AX-minimized are dropped (they're on other Spaces). Matches CG windows to AX windows by exact CGWindowID (`_AXUIElementGetWindow`), then title, then bounds proximity (see Invariant 6). Optional filters read from SettingsStore at summon time: `windowScope` (all displays vs pointer's display — bounds converted Quartz→Cocoa via `primaryHeight - maxY`, straddling windows count on both, minimized windows use stale pre-minimize bounds) and `frontAppScope` for the Opt-\` mode (bundle-ID clubbing vs exact frontmost PID).
- `AppRecencyTracker` — MRU order from `NSWorkspace.didActivateApplicationNotification`, keyed by **bundle ID (app key)**, not PID — apps with one process per window (Ghostty) must stay clubbed. The `.allProcesses` front-app filter in the catalog uses the same key. The main list itself is sorted by **window-level** recency (global z-order of the on-screen query — focusing raises, so z ≈ focus order); the app-level rank now only orders minimized windows at the list's end.
- `WindowActivator` — unhide → cooperative `app.activate(from: frontmostApp, options: [])` (the deprecated `activateIgnoringOtherApps` flag is a no-op on macOS 14+ and can silently fail; only used as a no-frontmost-app fallback) → **WindowServer-level front+key for the exact window**: `_SLPSSetFrontProcessWithOptions(psn, wid, userGenerated)` + `SLPSPostEventRecordTo` make-key event (synthetic left-mouse-DOWN delivered by window id, aimed at (300000,300000) so no content can be clicked — AltTab/yabai's recipe; symbols resolved via dlsym, no private-framework link flags) → AX unminimize → `kAXRaiseAction` + set main/focused, then +150ms/+450ms verify-and-retry passes (activation is async; immediate focus calls can land before the app is frontmost and get dropped; Chrome materializes a window's AX node only after it gets keyed, so retry passes re-resolve the element and self-heal).
- `SwitcherPanelController` — one `SwitcherPanel` per `NSScreen` (switcher shows on all monitors, identical clones keyed by `NSScreenNumber`); drops all cached panels on `didChangeScreenParametersNotification` and recreates lazily on next show (cached `NSScreen` objects go stale on rearrangement).
- `SwitcherPanel` — borderless `.nonactivatingPanel`, `.canJoinAllSpaces + .fullScreenAuxiliary`, all keys handled by the event tap so the panel never takes key status. Sized via `NSHostingController.sizingOptions = [.preferredContentSize]` + KVO on `preferredContentSize` (SwiftUI lays out asynchronously — never read a size in the same run-loop tick as a model change; that was a real bug). Position is always derived from the screen's `visibleFrame`, never from the panel's current frame — keep-center math drifts when animated resizes chain.
- `SwitcherViewModel` — `@Observable`; selection defaults to row 1 (quick-toggle to previous window).
- **Theming (opt-in, off by default)** — `ThemedSwitcherPanelController` owns one pre-warmed `ThemedSwitcherPanel` **per screen** (mirroring `SwitcherPanelController`; dropped and lazily rebuilt on display-config changes). Each panel hosts a locked-down WKWebView rendering the user's theme with its own `SwitcherBridge`, but all bridges observe the same view model, so selection/highlight stay in lockstep across displays; a click on any panel confirms. **Panel placement ≠ catalog scope**: the window list always follows `windowScope` regardless of theme — a theme must never filter out other displays' windows (this regression shipped once: `usingTheme` leaked into the `limitTo:` argument). "Active display only" scope shows the themed panel on the pointer's screen and hides the rest. `SwitcherBridge` pushes the view model as JSON into `window.alter.update(...)` (via `withObservationTracking`, re-registered per fire with a next-tick hop — onChange sees stale values) and validates incoming select/confirm/resize/error messages. `AlterSchemeHandler` serves `alter-icon://<pid>`, `alter-shot://<windowId>?maxw=N` (via `WindowThumbnailer.captureOnDemand`, bucketed to 256px steps, session-cached) and `alter-lib://<name>` (bundled helper assets, allowlisted to `alter-elements.js` only — never serve arbitrary bundle resources). `alter-elements.js` (a bundled resource at `Alter/alter-elements.js`) defines the optional `<al-list>`/`<al-icon>`/`<al-shot>`/`<al-preview>` custom elements + `alter.autoResize()`; themes load it with `<script src="alter-lib://alter-elements.js">`. The webview is local-only: navigation restricted to the theme dir + alter-* schemes, http(s) blocked via WKContentRuleList, nonPersistent data store. **First show after a (re)load is gated** (pendingShow until didFinish + settle beat, or the first post-render resize for `"size": "auto"` themes; 0.6s hard cap) so the panel never flashes intermediate sizes — autoResize deliberately starts measuring only after the first state render. A theme JS error, load failure, or WebContent crash latches `themeFailed` in the coordinator and falls back to the built-in UI until the theme selection changes. Dev overrides: `ALTER_THEMES_DIR` (theme root) + `ALTER_THEME` (theme id, unpersisted).
- `WindowThumbnailer` — ScreenCaptureKit thumbnails (`SCShareableContent` matched by CGWindowID, `SCScreenshotManager.captureImage`, 4-concurrent limiter). Session-scoped (`beginSession` on show / `endSession` on dismiss); a generation counter drops late results. Callers must be on the main thread. Without Screen Recording permission, captures fail silently and the preview pane is not shown at all.
- `SettingsStore` — `@Observable`, UserDefaults-backed; `onTriggerModifierChange` callback applies changes live (no restart). Search settings (`searchEnabled`, `searchTriggerModifier`) apply live the same way via `onSearchSettingsChange`.
- `Permissions` — AX (`AXIsProcessTrustedWithOptions`) and Screen Recording (`CGPreflightScreenCaptureAccess`); Settings polls both every second while open.

## Invariants / gotchas (do not break)

1. **Never swallow more than the configured trigger combos.** The other modifier (Cmd in Option mode, Option in Command mode) and Control must pass through — users rely on Cmd-Tab falling back to native in Option mode. **Exception:** while the search panel is visible it also swallows the keys it owns (Escape/Return/arrows/Delete + printable characters); anything with Command/Control still passes through.
2. **Panel must stay non-activating.** Focus must remain with the user's app so "frontmost app" (used by Opt-` filtering) doesn't become Alter. This also applies to the search panel — its text field is rendered manually and fed by the event tap.
3. **Exclude the switcher panels by window ID** (NSWindow.windowNumber == kCGWindowNumber) — never by own PID, so Alter's other windows (Settings, permission onboarding) stay listed and switchable. The search panel's window ID is excluded the same way (`SearchCoordinator.windowIDs`).
4. **Ad-hoc signing invalidates TCC grants on every rebuild.** Keep the Apple Development identity (`CODE_SIGN_IDENTITY`, `DEVELOPMENT_TEAM = 29DC9FRNK7` in the pbxproj). If the user reports re-prompts every build, check this first.
5. If codesign hangs during build, it's a keychain prompt/lock — `security set-key-partition-list -S apple-tool:,apple:,codesign: -s ~/Library/Keychains/login.keychain-db` fixes it (asks user password).
6. CG↔AX window matching: exact CGWindowID first via the private-but-stable `_AXUIElementGetWindow` (same symbol AltTab/Amethyst use), falling back to title then bounds heuristics. Keep the fallback — the symbol is undocumented. Bounds of minimized windows can be stale — don't make heuristic matching stricter without handling that. **Chrome-class apps have lazy AX trees**: an untouched window can be entirely absent from `AXWindows` (and AX titles carry a " - Google Chrome - <profile>" suffix, so title equality never matches Chrome). Never rely on an AX element existing at confirm time — that's why WindowActivator fronts/keys by window id at the WindowServer level first.
7. **Icon doesn't update in Dock/Finder after changing the asset catalog** — it's the LaunchServices cache, not the build: `touch` the built .app, `lsregister -f <app path>`, then `killall Dock; killall Finder`.
8. **WKWebView only renders in a bundled app.** A bare `swiftc` binary shows a webview window as on-screen in CGWindowList but renders it invisible with clicks passing through. Any standalone test harness must be a .app bundle (Info.plist + ad-hoc codesign) or it produces false negatives.
9. **Never combine `.fixedSize(vertical: true)` with `.frame(maxHeight:)` on a ScrollView.** fixedSize makes it ignore the height proposal and report full content height; the frame then clamps only the outer bounds and centers the over-tall, unclipped list — rows spill over sibling views above/below (this bug shipped in both panels). A ScrollView already reports `min(contentHeight, proposal)`, so `frame(maxHeight:)` alone fits short content and clamps long content with clipping.

## Known limitations (documented in README too)

- Other-Space windows excluded (needs private SkyLight Space APIs — avoid unless explicitly requested). Note: two NON-Space SkyLight symbols ARE used for reliable per-window activation (see `WindowActivator`); the Spaces APIs remain out.
- Hidden (Cmd-H) apps' windows excluded.
